Cryptunnel 隧道客户端 · 界面分析与优化方案

对象：v1.2.0（玻璃拟态 + 霓虹暗色，自定义无边框窗口） · 分析基于实际 XAML 与 MainWindow.xaml.cs 行为 · 2026-09-02
总体评价。 v1.2.0 把白底传统风格升级为玻璃拟态 + 霓虹暗色，视觉统一、现代感强；健康概览、流量微条、告警徽章已做到实时绑定；空状态引导、拖拽导入、暗色下拉等细节到位。作为「更猛」方向是合格落地。 但作为长期使用的运维工具，在 窗口行为正确性、一致性、可发现性、可维护性 上仍有明显可优化点。下面按严重度分级，并给出落地节奏。

一、亮点（建议保留）

  • ✓ 设计令牌统一（Tx1–3 / Accent / Success / Warn / Danger / Glass / Hair），暗色玻璃质感一致。
  • ✓ 顶部 4 张健康概览卡实时绑定 ProjectVm，属性变化即刷新，无需手动刷新。
  • ✓ 状态点 + 药丸、流量微条（log 刻度）、告警徽章——信息密度高且直观。
  • ✓ 空配置引导覆盖层 + 拖拽导入 YAML，上手门槛低。
  • ✓ 自定义无边框窗口 + 标题栏拖拽 / 最小化 / 最大化 / 关闭，霓虹「J」Logo。

二、问题分析

A. 窗口行为（正确性）

#问题影响
A1 最大化遮挡任务栏。 WindowStyle=None + GlassFrameThickness=0 时，WindowState=Maximized 会铺满整屏、盖住任务栏（WPF 已知坑，代码 BtnMax_Click 仅切换状态、未做 WorkArea 限制）。 高 · 运维常需边看日志边看别的窗口，最大化后找不到任务栏是低级吐槽点。
A2 无最小尺寸约束。 未设 MinWidth/MinHeight，窗口可被拖到极小，8 列表格被压扁、日志区消失、布局崩坏。 中 · 缩窗口即破相。
A1 示意：无边框最大化铺满显示器（含任务栏区域）

B. 一致性与导航

#问题影响
B1左栏「项目(▦)」是死按钮。 IsEnabled="False" 却用渐变背景高亮，看起来像可点功能、实际无效，且与右侧项目表格语义重复。中 · 误导点击、显脏。
B2图标用 Unicode 字形（▦ ＋ ≣ ⚙ — ▢ ✕）。 不同字体/系统可能显示为豆腐块，尤其 ▢（最大化）、≣。中 · 跨环境不一致。
B3「操作」列三按钮窄列拥挤。 Width=160 + 三个 MinWidth 按钮，窗口变窄时文字截断（HorizontalScrollBarVisibility=Disabled 导致列被压缩而非出横滚）。中 · 窄屏不可读。

C. 信息表达

#问题影响
C1概览卡标题与副标题语义重复/含糊。 「隧道总数」副标题「配置目录项目数」≈重复；「已连接」副标题「运行中隧道」≈同义；「累计流量」主数字 ↓ X ↑ Y 无单位提示。中 · 信息冗余、口径不清。
C2告警列两徽章点击都打开同一明细窗且不过滤级别。 点「警告」徽章也会看到错误，区分度弱（BtnShowErrors/BtnShowWarnings 都 new ErrorDetailWindow(...) 无 level 过滤）。中 · 操作预期不符。
C3流量微条 0 字节仍画 3px。 BytesToBarWidthConverter 用 Max(3,…)，0 流量看起来「有一点」，不够诚实。低 · 视觉小瑕疵。

D. 可发现性 / 引导

#问题影响
D1拖拽导入仅空状态有提示。 有项目后用户不知仍可把 YAML 拖到窗口任意处导入（Window_Drop 对全窗口生效）。中 · 能力被埋没。
D2主操作无快捷键。 新建 / 重载 / 定位日志均无 KeyBinding。低 · 效率损失。

E. 可访问性

#问题影响
E1次要文字对比度偏低。 Tx3(#6c7890) 用于列头(11px)、副标题等小字，暗底对比度约 4:1，接近 WCAG AA 下限 4.5:1，小字号吃力。低 · 暗环境可读性问题。
E2无浅色 / 高对比主题。 部分用户在亮环境看暗色吃力。低 · 可选。

F. 可维护性（为后续迭代铺路）

#问题影响
F1样式全内联在 MainWindow.Resources（~320 行），且 ErrorDetailWindow.xaml 又复制一套设计令牌。 改一处要改两处，易漂移。中 · 回归风险。
F2无边框外壳逻辑只写在 MainWindow。 ErrorDetailWindow / ProjectEditorWindow 也 WindowStyle=None 但没 WindowChrome，最大化行为不一致。中 · 行为分裂。

三、优化方案（按优先级）

P0必做 · 影响日常可用性（改动小、收益大）
  • A1 最大化不挡任务栏： 在 MainWindow 挂 HwndSource 钩子处理 WM_GETMINMAXINFO，最大化时把窗口矩形限制在 SystemParameters.WorkArea；最大化态圆角设为 0。建议抽成通用 WindowChromeBehavior 复用给其它窗口（顺带解决 F2）。
  • A2 最小尺寸： 设 MinWidth="980" MinHeight="640"，保证 8 列表格至少可读、日志区不消失。
P1强烈建议 · 体验与一致性（多数纯 XAML / 小逻辑，可一轮迭代做完）
  • B1 左栏死按钮： 改为顶部品牌区（不可点的「J」+ 应用名），或移除，把栅格留给 3 个真实功能（新建 / 日志 / 配置）。
  • B2 图标矢量化的： 用 Path（Segoe MDL2 / 自制几何）替换 Unicode 字形，保证跨环境一致。
  • C1 概览卡口径： 副标题改为信息量更高的说明，如「运行中 / 总数」「错误隧道数」「自启动以来累计」；流量主数字补单位（B/KB/MB）。
  • C2 告警明细过滤： ErrorDetailWindow 支持按 level 过滤（错误徽章→只看错误，警告徽章→只看警告），或加级别 Tab。
  • C3 流量微条 0 值： b==0 时返回 0（不画条），或画一条极淡基线。
  • D1 拖拽导入常驻提示： 工具栏/表格区加淡提示「可拖入 YAML 导入」，或拖动悬停时高亮拖拽热区。
  • D2 快捷键： 加 Ctrl+N 新建、Ctrl+R 重载、Ctrl+L 定位日志（InputBindings）。
P2打磨 / 长期
  • E1 对比度： Tx3 提亮到 #8a96ad 左右，或列头/副标题改用 Tx2。
  • F1 抽主题资源字典： 建 Theme.xaml / Controls.xaml（设计令牌 + 按钮/ComboBox/DataGrid/Toggle 样式），多窗口 MergedDictionaries 共用。
  • F2 通用 WindowChromeBehavior： 统一三个窗口无边框行为（含最大化不挡任务栏）。
  • E2 可选浅色 / 高对比主题。

四、建议落地节奏

第 1 步（P0）： 先修 A1 + A2——改动最小、收益最大，直接消除「最大化找不到任务栏 / 拖小破相」两类低级吐槽。
第 2 步（P1）： 一致性 + 可发现性一轮迭代做完（B1/B2/C1–C3/D1/D2 基本是 XAML 与小逻辑）。
第 3 步（P2）： 抽资源字典 / 通用 Behavior 结合下次大改一起做，避免现在动一大片引发回归。

说明：本分析基于 v1.2.0 已落地的 MainWindow.xaml / ErrorDetailWindow.xaml / MainWindow.xaml.cs 实际代码与行为，未做主观臆测。A1 最大化行为已对照 BtnMax_Click 实现确认无 WorkArea 限制；C3 已对照 BytesToBarWidthConverter 的 Max(3,…) 确认。其余为可观测的布局/交互事实。
